# Recorded sessions

Generated by `scripts/index_recordings.py`. One row per directory under `recordings/sessions/`.

**The bags are NOT in this repository.** They are multi-gigabyte `.mcap` files, over GitHub's 100 MB per-file limit, and `recordings/sessions/*/bag/` is gitignored. What IS here is the part you read: `trail.csv`, `summary.json`, `events.jsonl`, `manifest.json` and the figures.

| | |
| --- | --- |
| sessions | 28 |
| with a summary (stopped cleanly) | 3 |
| bags on disk, not in git | 15.5 GB |

**`channels DEAD` is the column that matters.** A recording where the master arm never published looks identical to one where it did, until you read that field. `figures` is the other tell: graphs are written on STOP, so a session with 0 figures was killed rather than stopped.

## What a session contains

| file | what is in it |
| --- | --- |
| `trail.csv` | 76 columns at ~19 Hz: sim and real joints (7 per arm), master pose and quaternion, commanded end-effector, and a freshness flag per channel |
| `summary.json` | duration, row count, channels live and DEAD, event counts, bag size |
| `events.jsonl` | one line per event: session start/stop, clutch, refusals with their reasons |
| `manifest.json` | label, mode, and whether shared autonomy was on — the condition the run was made under |
| `arms.jsonl` | both real arms read straight off the Kortex API |
| `figures/` | `clutch`, `freshness`, `joints_left`, `joints_right`, `trails` |
| `bag/` | every ROS topic. **Not in git.** |
